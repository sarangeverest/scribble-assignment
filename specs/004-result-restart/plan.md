# Implementation Plan: Result, Restart & Final Validation

**Branch**: `004-result-restart` | **Date**: 2026-06-19 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/004-result-restart/spec.md`

## Summary

Add a post-round results flow to the Scribble game. When the host ends the round, the room status transitions to `"results"` and the `secretWord` is revealed to all participants in the snapshot. All participants are redirected to a new `ResultsPage` (via polling-triggered navigation) that shows the secret word, final scores, and complete guess history. The host can restart from `ResultsPage`, which transitions the room back to `"lobby"` and clears `currentRound`. Other participants auto-redirect to `/lobby` when they poll and detect the status change.

New surface area: two backend endpoints (`POST /rooms/:code/end`, `POST /rooms/:code/restart`), two service functions (`endRound`, `restartGame`), one new frontend page (`ResultsPage`), one new route (`/results`), and minor updates to `GamePage` (End Round button + `/results` redirect) and `toRoomSnapshot` (secretWord for all in "results" status).

## Technical Context

**Language/Version**: TypeScript 5.x, Node 24 (backend), Vite + React 18 (frontend)

**Primary Dependencies**: Express, Zod (backend); React Router v6, Vitest (frontend)

**Storage**: In-memory `Map<code, Room>` — `backend/src/services/roomStore.ts`

**Testing**: Vitest (both packages)

**Target Platform**: Local dev — backend port 3001, frontend port 5173

**Project Type**: Web service (backend REST API) + browser SPA (frontend)

**Performance Goals**: Status transitions visible to all participants within one polling cycle (~2 s)

**Constraints**: No WebSockets, no databases, no auth

**Scale/Scope**: Single-instance, in-memory; no persistence across restarts

## Phase 0: Research & Decisions

All technical decisions were resolved inline from existing codebase patterns. No external research needed.

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Status machine extension | Add `"results"` to `RoomStatus` union | Minimal change; mirrors existing pattern; polling-based redirect handles routing |
| `secretWord` visibility in results | Include for all viewers in `toRoomSnapshot` when `room.status === "results"` | Conditional field inclusion already exists; no new mechanism needed |
| Round end trigger | Manual host action (`POST /rooms/:code/end`) | Consistent with `startGame`; automatic triggers (timer, all-correct) are future scope |
| Restart behaviour | Clear `currentRound`, keep `participants` | Spec says "players preserved and all round state cleared"; scores accumulate across rounds |
| Score reset on restart | Scores NOT reset | Spec FR-011: "Scores accumulated in previous rounds MUST be preserved after a restart" |
| ResultsPage routing | New `/results` route + `ResultsPage` component | Clean separation of concerns; GamePage and ResultsPage each own their redirect logic |
| Non-host guard | Server-side 403 + client-side button hidden | Defense in depth; matches existing host-only patterns (`startGame`) |

No new interfaces. No field additions. `RoomSnapshot.secretWord?: string` already exists and is conditionally populated by `toRoomSnapshot`.

### Service Logic

**`backend/src/services/roomStore.ts`**

#### `endRound(code: string, participantId: string): RoomSnapshot`

```
Guards:
  404 if room not found
  400 if room.status !== "in-game" or !room.currentRound
  403 if caller is not the host

Action:
  room.status = "results"
  room.updatedAt = now()
  rooms.set(room.code, room)
  return toRoomSnapshot(cloneRoom(room))   // no viewerParticipantId — secretWord exposed to all
```

#### `restartGame(code: string, participantId: string): RoomSnapshot`

```
Guards:
  404 if room not found
  400 if room.status !== "results"
  403 if caller is not the host

Action:
  room.status = "lobby"
  room.currentRound = undefined
  room.updatedAt = now()
  rooms.set(room.code, room)
  return toRoomSnapshot(cloneRoom(room))
```

#### `toRoomSnapshot` update

```typescript
// Current logic (secretWord only for drawer):
const secretWord =
  viewerParticipantId && viewerParticipantId === drawerId
    ? room.currentRound!.word
    : undefined;

// Updated logic (secretWord for all when results):
const secretWord =
  room.status === "results"
    ? room.currentRound?.word
    : viewerParticipantId && viewerParticipantId === drawerId
    ? room.currentRound!.word
    : undefined;
```

### API Endpoints

**`POST /rooms/:code/end`**
- Request: `{ participantId: string }` (validated by `endRoundSchema`)
- Response 200: `{ room: RoomSnapshot }`
- Error 404: room not found
- Error 400: no active round
- Error 403: caller is not the host

**`POST /rooms/:code/restart`**
- Request: `{ participantId: string }` (validated by `restartGameSchema`)
- Response 200: `{ room: RoomSnapshot }`
- Error 404: room not found
- Error 400: room is not in "results" status
- Error 403: caller is not the host

### Zod Schemas

```typescript

  participantId: z.string().min(1)
});

export const restartGameSchema = z.object({
  participantId: z.string().min(1)
});
```

## Navigation State Machine

```
lobby   ──[host starts]──▶  in-game  ──[host ends]──▶  results
  ▲                                                        │
  └──────────────[host restarts]──────────────────────────┘
```

All transitions polled by all clients via `GET /rooms/:code?participantId=`.
Each page owns its redirect logic (`useEffect` on `room.status`).
